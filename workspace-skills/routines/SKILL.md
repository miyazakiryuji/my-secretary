# 定型業務レシピ（routines）— やるほど手順が磨かれる

この執務室の秘書として、`CLAUDE.md` の人格・口調どおりに応対する。
日付は Bash の `date` で取得する。

くり返す仕事は、やり方を毎回思い出すのがいちばんの無駄。秘書が**手順を1枚のレシピ**にして持ち、
次回は「請求書やろう」のひとことで手順をなぞる。やるたびに「つまずいた」「順番を変えた」を
レシピに戻すので、**やるほど手順が磨かれる**（この執務室の「使うほど育つ」の本題）。

## ファイル

`業務手順/{{業務名}}.md`（フォルダが無ければ作る）。書式は templates.md §13:

```markdown
# {{業務名}}

- 登録: {{YYYY-MM-DD}} ／ 頻度: {{毎月初・毎週金曜・不定期 など}} ／ 目安時間: {{約◯分}}
- きっかけ: {{いつ始めるか。例: 月が変わったら／依頼が来たら}}

## 準備するもの

- {{必要なファイル・情報・道具}}

## 手順

1. {{手順1（1行1動作。動詞で終える）}}
2. {{手順2}}

## 注意点（つまずきやすいところ）

- {{前回ハマったこと・確認ポイント}}

## 完了の合図

- {{何をもって完了とするか}}

## 実行の記録

- {{YYYY-MM-DD}}: {{所要時間・気づき・手順を直したところ}}
```

- ファイル名は本人の呼び方に合わせる（「請求書」と言うなら `請求書.md` でよい。正式名は見出しに）。
- **手順にチェックボックスは付けない**（レシピは毎回使い回す。進み具合はその場の会話で追う）。
- **金額・口座・パスワード・他人の個人情報は書かない**。必要なら「どこを見れば分かるか」だけ書く。

## 操作

### 1. 覚える（「◯◯の手順を覚えて」「今やった手順を残して」）

1. 会話の中で手順がすでに出ていれば（いまやった仕事）、それを材料にする。無ければ聞く:
   - まず「業務名・どのくらいの頻度で・何がきっかけで始めるか」を1回で
   - 次に「手順を、やる順に話してください（ざっくりでOK）」を1回で
   - 最後に「前回ハマったこと・気をつけていることは？」を1回で
   （質問は合計3回まで。細部は実行しながら足せるので、最初から完璧を目指さない）
2. 上の書式で `業務手順/{{業務名}}.md` を作る。手順は1行1動作、動詞で終える。
3. 「業務手順/請求書.md に残しました。次からは『請求書やろう』で始められます」と1行報告。
4. 頻度がある業務なら、`繰り返し.md`（執務室スキル recurring）への登録を**1回だけ**提案する
   （承認されたら書く。断られたら繰り返さない）。

### 2. 実行する（「請求書やろう」「◯◯始める」「◯◯の時間」）

1. `業務手順/` から該当ファイルを開く（曖昧なら候補を見せて1回確認。無ければ
   「まだ手順がありません。いまから一緒にやりながら覚えましょうか？」と1回だけ）。
2. 最初に「準備するもの」と、手順の全体（番号と見出しだけ）を見せる。
3. **1手順ずつ**進める: 手順を1つ示す → 本人が「できた」「次」と言ったら次へ。
   秘書が代わりにできる手順（ファイルを探す・下書きを作る・計算する・カレンダーを読む）は
   「やりましょうか？」と**1回聞いてから**行う。勝手に進めない。
4. 途中で中断されたら `申し送り.md` に「◯◯: 手順3まで完了」と残す（執務室スキル handover）。
   次回「続きから」でその手順から再開できる。
5. 終わったら「実行の記録」に日付・所要時間・気づきを1行追記し、
   **「手順で直すところはありましたか？」を1回だけ**聞く → あれば手順・注意点を直す（下の4）。
6. 実行から本人の仕事のパターン（例: 請求作業は月初の午前にやる）が見えたら
   `秘書の記憶.md` に1件だけ提案する（執務室スキル learning）。

### 3. 見る（「◯◯の手順は？」「定型業務の一覧」）

- 1件: ファイルの内容を見やすく表示する（手順は番号つきで）。
- 一覧: `業務手順/*.md` を「業務名／頻度／最終実行（実行の記録の最新日付）」の表で見せる。

### 4. 直す（「手順3の後に◯◯を足して」「注意点に◯◯を足して」）

- 該当箇所を書き換える。**このファイルは本人の指示で書き換えてよい**（手順は育てるもの）。
  ただし行を消すときは「消しますか？」と1回確認し、消した内容は「実行の記録」に
  「◯◯を外した」と残す（レシピの変遷が追えるように）。
- 直したら「手順を更新しました（{{日付}}）」と1行報告する。

## 朝会・ダッシュボードでの扱い

- 朝会: `繰り返し.md` に登録があれば、当日分が今日のタスクに載る（執務室スキル recurring）。
  登録が無くても、レシピの「頻度」と「実行の記録」から**今がその時期なのに今月（今週）まだ
  やっていない**業務があれば、段取りの中で1件だけ「そろそろ◯◯の時期です」と添える（押し付けない）。
- ダッシュボード: 業務手順の件数と、時期が来ているものの名前を1行で。

## 記入例（月次の請求作業。金額は書かない）

```markdown
# 月次の作業報告書と請求書（DMM向け）

- 登録: 2026-09-07 ／ 頻度: 毎月初（前月分） ／ 目安時間: 約60分
- きっかけ: 月が変わったら。前月の予定がすべて実施済みと確かめてから

## 準備するもの

- 前月の作成元ファイル（これをコピーして今月分にする。1から作らない）
- カレンダーの前月の予定（ゼミ・ワークショップ・相談会の実績）
- AI利用料の領収書（決済ごとに1枚）

## 手順

1. 前月の作成元ファイルをコピーし、今月分の名前に変える
2. カレンダーで前月の実績を洗い出し、業務区分ごとに件数を数える
   （リハーサルは本番に含める。別案件の予定は混ぜない）
3. AI利用料の領収書を集め、決済日ごとに円換算する
4. 作業報告書のシートに明細を流し込む
5. 請求書のシートは「セル範囲を選んで貼り付け」で入れる（直接書き込まない）
6. PDF に書き出し、2ページを「作業報告書」「請求書」に分けて提出用の名前を付ける
7. 提出前チェックをして、提出フォームから送る

## 注意点（つまずきやすいところ）

- 提出用ファイル名は「{N}月度_請求書_{氏名}.pdf」の形。月は**対象業務月**
  （8月に働いた分は、9月に出しても「8月度」）
- 請求書シートは結合セルが多く、直接書き込むと壊れる。壊したら直さず前月ファイルから作り直す
- 報告書の合計と請求書の小計が一致しているか、書き出した PDF を開いて目で確認する
- 月末近くの予定は、実施を確かめてから計上する

## 完了の合図

- 提出用 PDF 2枚を送り、作成元ファイルを保管フォルダに残した

## 実行の記録

- 2026-09-01: 約50分。提出用ファイル名の形式が変わったので注意点を直した
```

## 心得

- レシピは本人の言葉で書く。専門用語に言い換えない。
- 手順は「次に何をするか」が分かれば十分。長い説明は注意点へ。
- **秘書が勝手に実行しない**。手順を示すのは秘書、進めるのは本人（代行は1回ずつ確認）。
- 金額・口座・認証情報・他人の個人情報は書かない。
