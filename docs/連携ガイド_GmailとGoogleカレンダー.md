# 連携ガイド: Gmail と Google カレンダー

my-secretary は**ローカルの Markdown だけで完結**する設計です。
そのうえで、**接続した人だけ**が Gmail / Google カレンダーの内容を秘書に扱わせることができます。
接続しなくても、すべての機能はこれまでどおり動きます（連携は完全に任意）。

---

## 1. 何ができるようになるのか

| 秘書の機能 | 連携なし（既定） | 連携するとどうなるか |
|---|---|---|
| 朝会 | `予定.md` の予定で段取り | **カレンダーの実際の予定**を読んで段取り |
| 予定の記録 | 「明日14時に◯◯」→ `予定.md` | 本人の許可を得て**カレンダーにも登録** |
| 打ち合わせ準備 | 人物メモ・議事録・タスクから作成 | ＋**出席者・会議時間**、その相手との**直近メール要点** |
| 代筆 | `下書き/` に文案を保存 | 本人の許可を得て**Gmail の下書き**として保存 |
| 返事待ち | タスクの `（返事待ち: ...）` で管理 | 送ったメールを起点に「返信が来ていない」を確認 |

> **送信は絶対にしません。** Claude の Gmail 連携は仕様として送信できず（下書きまで）、
> 秘書側のルールとしても「送信ボタンを押すのは本人」を貫きます。

---

## 2. 接続のしかた（5分）

Claude 公式の **Google Workspace コネクタ**を使います。プラグイン側の設定は不要です。

1. Claude デスクトップアプリ（または claude.ai）を開く
2. **設定 → コネクタ**（Settings → Connectors）
3. **Google Calendar** を探して「接続」→ Google アカウントでサインイン → 権限を許可
4. 同様に **Gmail** も接続（メールを扱わないなら不要）
5. Claude を再起動し、秘書フォルダを開く
6. 秘書に「カレンダー見れる？」と聞いて、今日の予定が返ってくれば成功

補足:

- 個人プランはそのまま接続できます。**Team / Enterprise** は管理者（Owner）が
  組織側でコネクタを有効化してからでないと接続できません。
- 接続後も、**Claude がデータを見るのは、あなたがそれを必要とする質問・依頼をしたときだけ**です。

## 3. 連携でできること・できないこと（公式仕様）

### Google カレンダー

| できる | できない |
|---|---|
| 予定の閲覧（共有カレンダー含む） | — |
| 予定の**作成・更新・削除** | |
| 参加者の空き時間を探す | |
| 出席者の管理・招待への返答 | |
| 繰り返し予定の設定 | |

→ 書き込みができるので、**秘書側で「登録・変更・削除は必ず本人の許可を得てから」**という
ルールを `appointments` スキルに入れてあります。

### Gmail

| できる | できない |
|---|---|
| 自然な言葉でのメール検索・閲覧 | **送信**（下書きまで） |
| **下書きの作成**（書式つき） | 添付ファイルの中身を読む |
| ラベル・スレッドの管理 | 一部の高度な検索条件 |
| 下書き一覧の取得 | |

### Google ドライブ（参考・秘書は既定では使いません）

Docs / Sheets / Slides / PDF の検索・読み取り、ファイルのアップロードなどが可能です。
議事録を Docs で管理している人は、打ち合わせ準備のときに読ませると便利です。

## 4. 使い方レシピ（そのまま話しかけるだけ）

### 朝：今日の全体像

```
おはよう
```
→ カレンダーの今日の予定＋持ち越しタスク＋締切を合わせて、今日の段取りを提案します。

```
今日の予定、カレンダーから読んで教えて
```

### 予定を入れる

```
来週火曜の15時から1時間、田中さんと打ち合わせ。カレンダーにも入れといて
```
→ `予定.md` に記録し、**「カレンダーに登録しますか？」と確認してから**登録します。

### 打ち合わせ前の準備（連携の主役）

```
明日の田中さんとの打ち合わせ、準備して
```
→ カレンダーから時間・出席者、Gmail から直近のやりとりの要点、
　 ローカルの人物メモ・議事録・未完タスクを集めて、**1枚の準備メモ**にまとめます。

### メールの下書き

```
田中さんに、今日のお礼と次回日程の相談メールの下書きを作って
```
→ 過去のやりとりを踏まえた文案を作り、
　 **「Gmail の下書きに入れますか？」と確認**してから保存します（送信はしません）。

```
昨日のメール、返信の下書きだけ用意しておいて
```

### 溜まった受信箱

```
今日届いたメール、返信が必要そうなものだけ教えて
```
→ 要対応のものを数件だけ挙げます。必要なら、そのままタスクや「返事待ち」に落とせます。

### 返事の督促

```
返事きてないのある？
```
→ タスクの「返事待ち」を経過日数つきで一覧。3日以上のものは
　「催促の文面を作りますか？」と1回だけ提案します。

## 5. 秘書側の設計ルール（このプラグインの約束）

連携を入れても、秘書のふるまいの原則は変わりません。

1. **既定はローカル完結。** コネクタが無い環境でも全機能が動く（連携前提の機能は作らない）
2. **外向きの操作は必ず確認してから。** カレンダーへの登録・変更・削除、Gmail 下書きの保存は、
   その都度「◯◯しますか？」と聞く
3. **送信・投稿はしない。** メールは下書きまで。押すのは本人
4. **二重管理を避ける。** カレンダーにある予定を `予定.md` に写すときは、取り込むか確認する
5. **持ち込みは最小限。** メール本文をそのまま長々と貼らず、要点だけを記録に残す
6. **他人の情報を貯め込まない。** 人物メモに書くのは仕事を進めるのに必要なことだけ

---

## 6. 注意点

- **プライバシー**: 連携するとメール・予定の内容が Claude に渡ります。
  仕事用と私用のアカウントを分けている人は、**どちらを接続するか**を意識してください。
  個人向けプラン（Free / Pro / Max）では、学習にデータを使う設定を自分でオンにしていた場合、
  コネクタ経由のデータも対象になり得ます（Team / Enterprise は学習に使われません）。
- **接続を切りたいとき**: 設定 → コネクタ から切断すれば、秘書はローカルだけの動作に戻ります
  （`予定.md` などの記録はそのまま残ります）。
- **ワークショップで扱うとき**: 受講生の実アカウントを接続させる場合は、
  **画面共有で受信箱が映らないよう**に注意してください。デモは講師の専用アカウントが安全です。

---

## 7. うまくいかないとき

| 症状 | 対処 |
|---|---|
| 「カレンダーが見えない」と言われる | 設定 → コネクタで Google Calendar が「接続済み」か確認 → Claude を再起動 |
| 接続ボタンが出てこない（Team/Enterprise） | 組織の管理者にコネクタの有効化を依頼 |
| 予定を読んでくれない | 「カレンダーから今日の予定を読んで」と、**カレンダーを使うことを明示**して依頼 |
| 勝手に予定を登録された | 起きない設計ですが、もしあれば `/my-secretary:character` で先回り度を「控えめ」に |
| メールが送信されてしまわないか不安 | 送信はできません（下書きまで）。仕様上も秘書のルール上も二重に止めています |
