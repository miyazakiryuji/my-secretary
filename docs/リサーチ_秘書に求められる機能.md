# リサーチ: 秘書アプリに求められる機能（2026-07-30 実施）

my-secretary の機能拡張を決めるために、**6つの角度**から Web 調査した結果と、
現プラグインとのギャップ・優先度をまとめる。出典は末尾。

---

## 角度1: 人間の秘書は実際に何をしているか

秘書の業務は大きく6つに整理されている（複数の求人・職種解説サイトで共通）:

| 業務 | 具体例 |
|---|---|
| **スケジュール管理・調整** | 会議・出張の予定調整、会議室の準備、当日の予定報告 |
| **来客・電話・メール対応** | 上司宛の窓口。応対、取次ぎ、返信 |
| **文書作成・管理** | 資料作成、議事録、ファイリング |
| **手配業務** | 交通機関・ホテルの予約、経費精算 |
| **情報収集** | 会議前の下調べ、関連情報の準備 |
| **庶務** | 備品管理、他部署との連絡調整 |

1日の流れの典型例は「**朝: メール確認→上司の予定確認→予定の報告**／日中: 会議準備・議事録・来客／
**夕: 出張手配・経費精算→明日の業務確認**」。

> **示唆**: 現プラグインは「タスク・メモ・日報」に強い一方、秘書業務の中核である
> **①予定（アポ）管理 ②人物・来客対応 ③メール・文書の代筆**が丸ごと欠けている。
> とくに①は「1日の流れ」の起点であり、朝会の質を決める。

## 角度2: オンライン秘書（代行サービス）に実際に依頼されている業務

日本のオンライン秘書サービス各社が「依頼できる業務」として掲げるもの:

- スケジュール調整・**アポイント管理**・メール対応・出張手配（＝秘書業務）
- 経理（請求書・経費）、人事、総務、営業事務
- 資料作成、リサーチ、Web運用

料金は「月◯時間で◯円」の時間制が主流 ＝ **依頼者は"自分の時間が空くこと"に金を払っている**。

> **示唆**: 「代わりにやってくれる」ことの価値が中心。記録するだけでなく
> **下書き・準備物を作る**（代筆・打ち合わせ準備）が、体感価値の大きい機能。

## 角度3: AIアシスタント市場（2026）で"必須"とされている機能

各種比較記事・製品レビューで共通して挙がる要件:

1. **永続メモリ（persistent memory）** — 2026年の最大の差別化要因。
   Salesforce の調査では、永続メモリを設定した人は **1日平均47分の短縮**。
   「毎回説明し直す」ことが最大の不満。
2. **プロアクティブ（先回り）** — 「聞かれる前に出す」。
   Lindy などは「メール・スケジュール・フォローアップを勝手に回す」ことを売りにしている。
3. **既存ツールとの統合** — Gmail / Google Workspace 連携は採用の前提条件。
4. **自動スケジューリング** — Motion（予定を自動再構築）、Reclaim（習慣ブロックを死守）。
   一方 Sunsama / Akiflow は**手動の"儀式"型**（毎朝の計画セッション）で、
   「少ないことを、意図的にやる」思想。**ここは思想の分岐点**。
5. **ローカル/プライバシー** — 「個人史をクラウドに渡したくない」層が local-first を選ぶ。

> **示唆**: my-secretary は 1（記憶）と 5（ローカル完結）を既に満たしており、
> **市場でも評価軸として上位の2点が最初から強み**。逆に 3（統合）が最大の弱点で、
> 4 は「儀式型（Sunsama 寄り）」を選択済み — これは**受講生向けには正しい選択**。

## 角度4: なぜタスク管理は続かないのか（離脱要因）

日本語記事で繰り返し指摘されるパターン:

1. 最初の数日は丁寧 → **タスクが溜まる** → 消化できないリストを見るのが嫌 → 開かなくなる
2. **入力の手間**（管理自体が仕事になる）
3. 操作が複雑・機能が多すぎる
4. タスクを細かく設定しすぎ、詰め込みすぎ
5. 「きっかけ→行動→報酬」のループが切れている

> **示唆**: my-secretary は 2（話しかけるだけ）3（コマンド不要）5（出迎え＝きっかけ、労い＝報酬、
> 勤続日数＝可視化）に対処済み。**未対策は 1 と 4** ＝「溜まった持ち越しの棚卸し」。
> 「やらないと決める」を秘書から提案する仕組みが要る。

## 角度5: ジャーナリング／振り返り系アプリの定番機能

- 朝夕のチェックイン（AIガイド付きプロンプト）
- **ムード（気分）記録とその推移**、週次インサイト、AIが見つける"テーマ"
- **ストリーク（連続日数）**とウィジェット常設で習慣化
- 1エントリ2〜3分の低負荷

> **示唆**: 朝夕チェックイン・週次・ストリークは実装済み。
> **未実装はムード記録と"テーマ抽出"** だが、業務秘書としては優先度中。
> 「1エントリ2〜3分」の低負荷原則は、既存の「質問は1つだけ」方針と一致。

---

## 角度6: メール／会議まわりの AI 機能

- **トリアージ**（緊急度・種別で分類）、**自分の口調での返信下書き**
- **フォローアップ督促**（相手から返信がない／自分が返し忘れている）
- **プレミーティング・ブリーフ**（会う相手の履歴・前回の話・論点を1枚に）
- Claude の Gmail コネクタは **読み取りと下書きのみ・送信はできない** ＝ 秘書の設計方針と一致

> **示唆**: 「返事待ち」の管理と「打ち合わせ準備」は、**Gmail/カレンダー連携なしでも
> ローカルで成立**し、連携するとさらに強くなる。連携前提の設計にしない。

---

## 補足: 信頼を壊さない設計（研究）

- **過剰な足場かけ（over-scaffolding）はユーザーの自律性を奪う**。
- 提案の**深さ・頻度をユーザーが調整できる**ようにすべき。
- 良いパターンは「AIが提案 → 人が理解 → 人が検証」の反復で信頼が積み上がる形。

> **示唆**: 既存の「提案は1回に1つ・断られたら繰り返さない」は研究と整合。
> さらに **"先回り度"をユーザーが選べる設定**を足すべき（控えめ／ふつう／しっかり）。

## 今回の実装方針（結論）

1. **秘書業務の穴を埋める3本**を執務室スキルとして追加 —
   `appointments`（予定）／`people`（人物・打ち合わせ準備）／`drafting`（代筆）
2. **続かない問題への処方**として、締切スキルに「返事待ち」を統合し、
   週次に**棚卸し（やめる決断の提案）**を追加
3. **信頼設計**として、先回り度（控えめ／ふつう／しっかり）をキャラ設定に追加
4. **Gmail/カレンダー**は「あれば使う・なくても完全に動く」任意連携として設計
   （詳細は `docs/連携ガイド_GmailとGoogleカレンダー.md`）
